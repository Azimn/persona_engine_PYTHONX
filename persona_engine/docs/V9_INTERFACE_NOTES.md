# Persona Engine v9 Interface Notes

v9 adds a semi-embodiment interface layer without changing the core authority model.

The interface is a consumer of organism state. It may submit user text through the normal input channel, but it must not mutate relationship, body, world, memory, symbol, pressure, belief, or identity state directly.

Public status is projected by the backend before the UI sees it. Raw floats remain private except in explicit debug mode. The status panel should render categorical values such as `guarded`, `steady`, `high`, or `quiet`, not infer those states from raw numbers.

Second-thought fragments are selected from the already-computed workspace frame. The UI does not invent them. If the core does not expose a fragment, the UI stays silent.

Proactive events are proposals generated by the core from open loops, body state, world state, and relationship state. Delivery should still pass through a normal engine event path. The UI should never create proactive content on its own.

For C99 conversion, keep these pieces separate:

- `public_state.py` becomes a public projection table over private state.
- `proactive.py` becomes a deterministic proposal selector.
- `second_thought.py` becomes a bounded workspace-fragment selector.
- `ui.py` is not part of the core port. It is a host adapter.

The C core should expose public status and proactive event proposals as structs. A host application may render them, but not author internal organism state.
